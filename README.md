# ALH Frame

Android 本地视频补帧工具。把 24/25/30fps 的素材按 2×、3×、4× 提升帧率，全部在本机完成，不上传、不联网。

代码不多：一个 Activity、一个分段并行引擎、一个 ffmpeg 落地管理，没有第三方依赖，也不用 Gradle。

## 它怎么工作

1. **探源**：用 `MediaExtractor` 数完视频轨样本，得到真实帧率与时长——容器里写的 `frame-rate` 常被取整（29.97 写成 30），直接拿来切段时间轴会漂。
2. **切段**：按时间轴均分，每段输出帧数按 `round(s1*outFps) - round(s0*outFps)` 精确分配，段与段之间不重不漏。
3. **并行补帧**：每段一个 ffmpeg 进程，走 `minterpolate` 的 MCI 模式（双向运动估计 + 遮挡感知 + 变尺寸块）。并发数由可用内存决定，单路预算 `250 + 260 × 百万像素` MB。
4. **拼接**：段输出 MPEG-TS，时间戳在滤镜里直接落到全局帧位，编完一段就按序追加进累加文件并删除自己，磁盘峰值约为成品的 1.1 倍。
5. **回封**：原音轨按 `copy → aac → 无音轨` 三级回退封装，成品经 MediaStore 写进相册 `Movies/ALH Frame`。

参数依据、实测数据、以及块匹配算法的天花板，写在 [docs/算法说明.md](docs/算法说明.md)。

## 实测

720p、30 → 60fps、60 帧真值素材，与真值比 SSIM / PSNR：

| 做法 | 耗时 | SSIM | PSNR |
| --- | --- | --- | --- |
| 复制帧 | 350 ms | 0.9754 | 30.45 |
| 线性混合 | 389 ms | 0.9758 | 32.96 |
| MCI + 双向（bidir） | 6466 ms | 0.9883 | 36.94 |
| **MCI + 双线性（bilat，当前默认）** | **3855 ms** | **0.9875** | **36.80** |

换 `bilat` 后快了 40%，SSIM 只掉 0.0008；4× 档差距更明显（8214 ms / 0.9692 → 5225 ms / 0.9768）。插值本身占全流程 85–90%，1080p 单进程约 240 ms/输出帧，多进程分段是唯一有效的加速方向。

## 下载与安装

发布页提供 1.0 的 APK：`com.alh.frame`，minSdk 24（Android 7.0），targetSdk 28。

```bash
adb install -r ALHFrame-1.0.apk
```

换签名包的必须先卸载旧版本。

## 从源码构建

不依赖 Gradle，一条命令：

```bash
bash build.sh
```

需要的 SDK / JDK / ffmpeg 从哪来、怎么放，见 [docs/BUILD.md](docs/BUILD.md)。

## 使用边界

- 只处理你自己有权处理的素材。素材来源、授权与后续传播由使用者负责。
- 首次启动需要阅读并同意免责声明，不同意会退出；之后条款常驻界面底部，随时可点开。
- 补帧结果受源画质、码率、运动复杂度与设备性能影响，会产生插值伪影、边缘抖动、鬼影，属算法固有特性。
- 处理占满 CPU 与磁盘，长片请插电、别锁屏。

## 已知限制

- 没有前台服务，处理中切后台可能被系统回收。
- 源文件会复制一份到私有缓存，大文件多占一份空间。
- VFR 源按平均帧率处理，时长有极小偏差。
- 4× 后输出帧率部分机型相册不认（如 30fps × 4 = 120fps）。
