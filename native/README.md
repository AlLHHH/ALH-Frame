# ALH Frame Standard — 自研补帧内核

单文件 C++17，无第三方依赖，不加载任何模型权重。它只做一件事：吃掉一串 YUV420p 帧，在每两帧之间生成 `倍率-1` 张中间帧，再吐出来。解码、编码、封装都交给外面的 ffmpeg。

文件：[`alhift.cpp`](alhift.cpp)，437 行。

## 命令行

```
alhift <in.yuv|-> <W> <H> <帧数> <out.yuv|-> [倍率=2] [选项=3]
```

- `in` / `out` 传 `-` 表示 stdin / stdout，用于接管道。
- `<帧数>` 是输入帧数，必须给准，内核靠它判断什么时候收尾。
- 输入必须是无头的 YUV420p，平面顺序 Y、U、V，行内无对齐填充（ffmpeg 的 `-f rawvideo -pix_fmt yuv420p` 就是这个格式）。
- 倍率可以是小数（24fps→60fps 就是 2.5），内核按累积相位取整出帧。
- 输出帧数 = `round(输入帧数 × 倍率)`，不额外多写一帧；进度行 `k=<i>` 打到 stderr，收尾一行 `wrote <n> frames dup=<d>`。

选项按位叠加：

| 位 | 含义 | 建议 |
| --- | --- | --- |
| 1 | 亚像素细化（抛物线插值） | 可开，收益 0.0002 级别，慢 20% |
| 2 | 时域矢量融合 | 不要开，实测 SSIM 从 0.9907 掉到 0.9386 |
| 4 | 严格权重（置信度恒为 1） | 开，720p 最好 |
| 8 | 4×4 精修 | 不要开，-2 dB |
| 16 | 多遍中值 | 无收益 |
| 32 | 最细层搜索半径 6 | 无收益 |
| 64 | 16px 块 | 不要开，-2.5 dB |
| 256 | 双线性矢量场 | 弱收益，可开 |
| 512 | 多假设 WTA | 无收益，慢 1.8 倍 |
| 1048576 | 稠密 LK 精修（窗口跨 3×3 块、窗口内矢量双线性采样）| 中性 |
| 8388608 | 逐像素稠密光流档（块匹配种子可选 + 全分辨率细化）| foreman -0.006，慢 2× |
| 16777216 | 光流用块匹配场做种子 | 实测更差，别开 |
| 1024 | 真实反向场 | 单独无用，配合 131072 才有意义 |
| 2048 | 一致性硬回退 | 实拍片 -0.001，别开 |
| 4096 | 去重复帧 | 按需，见下 |
| 8192 | 匹配前 3×3 模糊 | 无收益 |
| 16384 | 逐像素可信度（σ=40） | 开，与 32768 一起用 |
| 32768 | OBMC 4-tap 重叠加权 | 开，减少块状接缝 |
| 65536 | 反向场遮挡权重 | 中性偏负，别开 |
| 131072 | 反向场候选选择 | **开**，实拍 +0.0046 |
| 262144 | 场景切换检测 | **开**，切镜不糊 |
| 524288 | LK 亚像素精修 | 开，实拍 +0.0023，慢 15% |
| 2097152 | Super SloMo 式双侧可见性 | 实测 -0.0013，别开 |
| 33554432 | 最细层搜索半径 8 | **开**，实拍 +0.0035，只慢 10% |
| 67108864 | 最细层搜索半径 12 | 数据不稳，别用 |
| 134217728 | 最细层搜索半径 16 | 再 +0.0014，但慢 60%，高分片不划算 |

默认 `3` 只是历史默认值。**推荐 `33997061`**（= 1|4|256|16384|32768|131072|262144|524288|33554432，即亚像素 + OBMC + 可信度 + 反向候选 + 场景切换 + LK + 最细层 rad8）；App 里就是这个值，勾去重时再 `|4096`。

## 接 ffmpeg（最常用）

```bash
# 30fps → 60fps，全程管道，不落中间文件
ffmpeg -i in.mp4 -an -f rawvideo -pix_fmt yuv420p - \
  | ./alhift - 1280 720 300 - 2 4 \
  | ffmpeg -f rawvideo -pix_fmt yuv420p -s 1280x720 -r 60 -i - \
      -c:v libx264 -crf 19 -pix_fmt yuv420p out.mp4
```

`300` 是源帧数。要接音轨就再套一层：把原始 `in.mp4` 作为第二路输入，`-map 0:v:0 -map 1:a:0 -c:a copy`。

有损流程要注意：`-pix_fmt yuv420p` 两边必须一致，中间不要插 `scale`，否则内核拿到的是错的平面尺寸。

## 编译

任何 C++17 编译器都行，源码没有平台相关代码：

```bash
# Linux / macOS
g++ -O2 -std=c++17 -o alhift alhift.cpp            # 或 clang++
g++ -O2 -std=c++17 -static-libstdc++ -o alhift alhift.cpp   # 想要可搬运的二进制

# Android（NDK r26 及以上）
$NDK/toolchains/llvm/prebuilt/<host>/bin/aarch64-linux-android24-clang++ \
  -O2 -std=c++17 -static-libstdc++ -o alhift-arm64 alhift.cpp
$NDK/toolchains/llvm/prebuilt/<host>/bin/x86_64-linux-android24-clang++ \
  -O2 -std=c++17 -static-libstdc++ -o alhift-x86_64 alhift.cpp

# Windows（MSVC）
cl /O2 /std:c++17 /EHsc alhift.cpp
```

Android 上不加 `-static-libstdc++` 会缺 `libc++_shared.so`。

## 算法

1. **金字塔**：源帧先 2×2 盒采样降到 `min(4, 1+log2(min(W,H)/40))` 层。
2. **块匹配**：每层 8×8 块做 SAD 全搜索，粗层半径 8，往下每层收窄到 2，最细层默认 3，位 33554432 切到 8（推荐，实拍 +0.0035，只慢 10%），67108864→12、134217728→16；两遍搜索（第二遍在前一遍结果附近细化），矢量幅度按 `0.02*(|dx|+|dy|)` 罚一下，避免平坦区乱跳。多线程按行切。
3. **后处理**：矢量场上采样 ×2，做 3×3 分量中值，抹掉孤立错矢量。
4. **合成**：`p0 = 双线性采样(a, x - v*t)`、`p1 = 双线性采样(b, x + v*(1-t))`，用匹配代价算置信度 `c = 1/(1+meanSAD²/900)`，权重 `w0 = (1-t)(0.35+0.65c)`、`w1 = t(0.35+0.65c)`；两边都越界时退化为两帧线性混合。色度按同块矢量搬运。
5. **去重复帧**（位 4096）：相邻两帧按 4 像素采样算平均绝对差，小于 0.8 判定为重复，直接复制当前帧、跳过整条估计链。对「原片本身重复帧」的素材能省一半算力。

## 实测

合成真值（60fps 逐帧已知），只算插帧，不含编解码：

真实拍摄素材 foreman（352×288，15→30fps，真值取实拍奇数帧，只比插出来的那些帧）：

| 配置 | SSIM | 相对 minterpolate（0.9478） |
| --- | --- | --- |
| 早期版本（opt 261） | 0.9288 | 差 0.019 |
| + OBMC + 逐像素可信度（49413） | 0.9369 | 差 0.011 |
| + 反向场候选（131072） | 0.9415 | 差 0.006 |
| + LK 精修（524288） | 0.9438 | 差 0.004 |
| + 最细层 rad8（33554432） | 0.9473 | 差 0.0005 |
| + 重叠窗代价 + 噪声自适应惩罚（默认） | 0.9488 | 追平 0.0002 |

合成素材 1280×720 30→60：干净片 0.9870（minterpolate 0.9864，耗时 13.1 s 对 14.4 s）；加噪片 0.8094（minterpolate 0.7838）。360×640 干净片 0.9907 / 39.79 dB，比 minterpolate 快一倍。

代价函数是这一轮最大的一笔：块匹配不再只算 8×8 块内 SAD，而是算块外扩 2 像素的 12×12 窗，再按 `pen × (|dx|+|dy|)` 惩罚位移。`pen` 由首帧噪声自动定：干净片取 0.25（对齐 ffmpeg 的 `COST_PRED_SCALE=64` 等效强度），σ 越大越松，下限 0.02——噪声让 SAD 不可靠时，重罚会把矢量场压回零矢量，画面反而糊。想手动干预可用环境变量 `ALH_PEN`（惩罚系数）、`ALH_WIN`（外扩像素）。

误差分布（紧挨着真值比）：运动区平均绝对误差 3.64 对 1.86，静止区 0.67 对 0.84。差距全在运动区的矢量精度上，所以唯一真正有效的旋钮是最细层的搜索半径。

试过但没收益的路子，别再走一遍：双向一致性校验、多假设 WTA、4×4 精修、16px 块、加大搜索半径、时域矢量融合、双线性矢量场、放大 2 倍再插值再缩回。全部被数据否决。

## 已知限制

- 实拍片与 `minterpolate` 打平（0.9488 对 0.9486）；720p 合成片领先（0.9870 对 0.9864），360p 领先约 0.004；速度略快（720p 30 对帧 13.1 s 对 14.4 s）。
- 不接 `trim` 单独用时，输出比 `N×倍率` 多 1 帧（末帧照抄），下游要自己裁。
- 只在整数像素上匹配（LK 精修只补亚像素），大位移、快速旋转的镜头仍会出错矢量。
- 没有遮挡推理，前景完全盖住背景时会糊一下。
- 块大小固定 8×8，物体运动小于一个块时矢量容易归零。
- 只吃 YUV420p，10-bit 和高色度采样不支持。
